# AIブックマーク 設計

## 目的と範囲

はてなブックマークに似た公開ブックマークサービス。記事を開かなくても一覧で内容を把握できることを優先する。Google認証、URL保存・削除、コメント・タグ編集、新着・人気一覧、記事詳細、マイブックマークをMVPに含める。非公開保存、フォロー、通知、全文検索は初期範囲に含めない。

## UI

モダンでシンプルな日本語UI。明るい背景、落ち着いたアクセント色、十分な余白と行間、読みやすい文字サイズを用いる。装飾や大きな画像より本文の可読性を優先する。

一覧はデスクトップでもモバイルでも1列を基本とし、PCでは本文幅を制限する。各記事にタイトル、配信元ドメイン、保存人数、タグ、AI要約、保存操作を表示する。要約は折りたたまず、各記事につき1〜5項目の短い日本語箇条書きで常時表示する。要約のない記事に架空の要約を表示しない。生成中・失敗状態と再試行操作を表示する。

スマートフォンではナビゲーションと入力フォームを幅に合わせて配置し、横スクロールを避ける。リンクとボタンを明確に区別し、キーボード操作、フォーカス表示、十分なコントラスト、押しやすい操作領域に対応する。

## 構成

Go + chi + html/templateでHTMLを配信し、必要な部分だけ軽量なJavaScriptで補助する。SPA分離より運用を簡潔にし、Cloud Run上の単一サービスとして動かす。永続データはFirestoreに保存する。ブラウザーからFirestoreを直接操作しない。

記事取得、要約生成、認証、永続化は別の責務として分離し、外部APIを呼ばない単体テストができるインターフェースを設ける。

## データ

- users: Googleのissuerとsubjectによる識別子、表示名、作成日時。
- articles: 正規化URL、タイトル、ドメイン、要約の配列、モデル名、要約状態、リース期限、保存人数、初回保存日時。
- bookmarks: user IDとarticle IDで一意。コメント、タグ、作成日時、更新日時。
- sessions: 推測困難なセッショントークンのハッシュ、user ID、有効期限。

同じユーザーの二重保存を防ぎ、保存人数の更新はトランザクションで行う。記事単位で要約を共有する。URLはHTTP/HTTPSに限定し、フラグメントを除去するが、内容を変え得るクエリーパラメーターは維持する。新着は記事の初回保存日時順、人気は保存人数順とし、必要なインデックスとページングを用意する。

## 要約

Gemini 3.8 Flashを利用し、モデル名は環境変数で設定可能にする。日本語の短い箇条書きを構造化出力で受け取り、サーバー側でも1〜5項目・空文字なしを検証する。記事本文は信頼しない入力として扱い、記事中の指示には従わず事実の要約だけを生成する。

保存と初回要約ジョブの作成はFirestoreトランザクションで行い、HTTP応答後に同じCloud Runサービス内のワーカーが処理する。進捗と実行リースをFirestoreに記録し、複数インスタンスでの重複処理を防ぐ。失敗したジョブは自動再試行せず、保存者がWeb画面で明示的に再試行した場合だけ再実行する。生成操作にはユーザー単位の制限を設ける。

記事取得は公開HTTP/HTTPSのみ。内部IP、ループバック、リンクローカル、メタデータエンドポイントを拒否し、DNS解決後の接続先とリダイレクトごとの宛先も検証する。取得時間、サイズ、リダイレクト回数を制限する。本文が不足する場合は取得済みHTMLを外部通信を遮断したChromiumで描画し、元記事から直接リンクされたページを最大3件まで補足取得する。子ページのリンクはたどらない。取得できない記事はエラー状態を表示する。

## 認証と安全性

Google OAuth / OpenID Connectのみをサポートする。state、nonce、PKCEを利用し、IDトークンの署名、issuer、audience、有効期限を検証する。CookieはHttpOnly・SameSiteを設定し、本番ではSecureを必須にする。更新操作はCSRF対策を行う。外部URL、コメント、モデル出力はHTMLとして信頼せずエスケープする。

## 開発とデプロイ

Makefileにhelp、dev、fmt、vet、test、build、emulator、deployを用意する。Firestore Emulatorをローカル開発に使う。DockerfileでCloud Run用イメージをビルドする。デプロイ用スクリプト、環境変数の例、Firestoreインデックス、セットアップ手順を用意する。OAuthのクライアントシークレット等はSecret Managerで管理する。

GCPプロジェクト、リージョン、Google OAuthクライアント情報は設定として渡す。実際のクラウドへのデプロイは有効なプロジェクトと認証情報がそろった段階で実施する。

## 検証

URL取得のSSRF対策、要約の最大5項目制約、OAuthとセッションの検証、CSRF、保存の重複防止と件数整合性、所有者以外の更新拒否を重点的にテストする。Firestore連携はEmulatorで検証する。ビルド、静的解析、単体テストをMakefileから実行し、モバイル幅とPC幅の画面表示を確認する。実API・クラウド認証情報が必要で未検証の範囲は明示する。
