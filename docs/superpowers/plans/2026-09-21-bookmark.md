# AI Bookmark Implementation Plan

**Goal:** 一覧で最大5項目の要約を読める、Google認証の公開ブックマークサービス。
**Architecture:** Go/chiでHTMLと操作エンドポイントを提供。Firestoreに記事・保存・セッション・制限を保存。記事本文の安全な取得後にGemini REST APIで要約。
**Tech Stack:** Go 1.26.8, chi v5, Firestore, coreos OIDC, OAuth2, Cloud Run.
**Spec:** ../specs/2026-09-21-bookmark-design.md

## Global Constraints
- Googleログインのみ。本番で認証を迂回するモードを作らない。
- 要約は1〜5個の箇条書き、一覧に常時表示。
- モバイル対応、HTMLエスケープ、CSRF、SSRF対策。
- Goの実行ファイルにテンプレートと静的ファイルを埋め込む。

## Tasks
- [x] 1. `internal/content`: URL正規化、公開IP限定取得、HTML本文抽出、Gemini構造化出力。URL/IP/要約境界テストを先に書き、`go test ./internal/content`で検証。
- [x] 2. `internal/store`: Firestore記事・ブックマーク・セッション管理。保存と削除はtransaction。Emulatorテストで重複、所有権、件数、生成リース、制限を検証。
- [x] 3. `internal/app`, `cmd/server`: 設定、OIDC/PKCE、CSRF、chiルート、ページング、保存、再試行。httptestで認証拒否とCSRF、公開HTMLを検証。
- [x] 4. `internal/web`: 白(#ffffff)、背景(#f4f7fb)、文字(#172b42)、補助(#526579)、線(#dce5ee)、青(#175cd3)。日本語システムフォント、ロゴのみGeorgia。各記事の要約を薄い青の縦線に沿って並べ、保存人数と元記事リンクを添える。320pxからの1列レイアウト。
- [x] 5. `Makefile`, `Dockerfile`, `scripts`, `README.md`: ローカル、Emulator、テスト、ビルド、Cloud Runデプロイと初期構築手順。秘密情報をリポジトリに含めない。
- [x] 6. `make test vet build`、Emulator統合テスト、PC/モバイルの画面確認、要件照合。実クラウドの認証情報がない場合は未検証範囲を明示。

このセッションで順番に実装し、追加の設計承認やコミットは行わない。
